# 디자인 가이드 — Charverse v2

> Charverse v2의 기획 요약과 화면 명세입니다. 화면·요소의 비즈니스 명칭은 실제 Flutter 구현과 맞추고, 리뷰 근거·사용자 여정·원칙·상태 표시를 함께 기록합니다.
> 화면을 변경할 때는 이 문서, 코드의 화면 대응표, 원칙 카드를 함께 갱신합니다.

| 항목 | 기획 |
|---|---|

### 사용자 여정

아래 감정 곡선은 리뷰와 구현 흐름을 바탕으로 한 **설계 가설**이며, 사용자 실험 측정값이 아니다.

| 단계 | 사용자 목표·행동 | 접점·현재 구현 | 리뷰 근거 | 예상 감정(1–5) |
|---|---|---|---|---:|
| 1. 학습 영역 선택 | 학습할 문자 체계를 빠르게 고른다. | A-7 허브에서 한글·히라가나·가타카나·한자·즐겨찾기를 선택 | R19의 주제별 분류 요청 | 4 |
| 2. 글자 찾기 | 검색·태그·획수 필터로 학습할 글자를 찾는다. | A-9 검색 및 필터, A-2 목록의 학습 상태·즐겨찾기 | R02 글자 표기 의견, R18 즐겨찾기·복습 요청 | 3 |
| 3. 글자 연습 | 글자 형태와 획 안내를 보고 직접 써 본다. | B-2 따라 쓰기 탭, B-3 캔버스, B-8 획순 토글, B-9 획 설명 | R02 표기 관련 의견 및 첨부 학습 화면 관찰 | 2 |
| 4. 피드백 확인 | 표시된 학습 피드백과 다음 행동을 확인한다. | B-2 피드백 탭의 GET 목업 데이터, B-6에서 여는 C 사전 작성 진단서 | R07 콘텐츠 오류에 따른 신뢰 우려 | 3 |
| 5. 학습 상태 정리 | 완료 상태를 표시하고 상태를 필요에 따라 되돌린다. | B-5 상태 조작, A-2 상태 배지와 완료 항목 정렬 | R08 학습 상태 관련 보고 | 4 |
| 6. 보상 확인 | 획득 캐릭터를 확인하고 테마를 선택한다. | 완료 안내 모달, D-2 미확인 표시, D-3 테마 선택·해제 | R18의 보관·복습 요청을 보상 재방문 흐름에 적용 | 4 |

감정 곡선의 최저점은 3단계의 글자 연습으로 설정했다. 글자의 표준 모양과 획 안내를 이해하기 어려울 수 있다는 리뷰·캡처 관찰을 반영한 가설이며, B-3·B-9에서 시각적 기준을 제공한다.

### 여섯 관점 검토

| 관점 | 확인 내용 | 화면·데이터 대응 |
|---|---|---|
| 모바일 UX | 짧은 세션에서 탐색·연습·상태 확인이 끊기지 않는가 | A 허브→목록→B 상세→C 모달 흐름, D 보관함 |
| 사용성 | 현재 선택·상태와 되돌아갈 방법이 분명한가 | A 검색·필터·학습 상태, B 탭·상태 복구, D 개별 확인·테마 해제 |
| 데이터 | 화면에 필요한 글자·태그·피드백이 표현되는가 | `db.json`의 162개 `items`, 6개 `notes`, 글자별 태그·획수 |
| API | 요청 방법과 화면 요소의 책임이 명확한가 | `lib/api.dart`의 GET `/items`, GET `/notes?itemId=`; 화면별 FutureBuilder |
| 네트워크 | 대기·실패·결과 없음에서 사용자가 다음 행동을 알 수 있는가 | 공용 `LoadingView`, `ErrorView`와 다시 시도, `EmptyView`; `DEMO_STATE` 시연 |
| 프로세스 | 기획·구현·검증 자료가 같은 명칭과 동작을 가리키는가 | 요소 번호, 화면 파일, 원칙 카드, 위젯 테스트를 연결 |

### 우선 쟁점 5 Why — 학습 상태가 의도와 다르게 보이는 경험

분석 대상은 R08의 학습 상태 관련 리뷰다. 아래 원인 단계는 공개된 리뷰 문장으로부터 세운 **설계 가설**이며, 원 앱의 내부 구현 원인을 단정하지 않는다.

| 단계 | 질문 | 분석 |
|---|---|---|
| Why 1 | 사용자는 왜 불편을 보고했는가? | 버튼을 눌러도 원하는 학습 단계로 이동하지 않는다고 느꼈다. |
| Why 2 | 상태 이동 실패가 왜 중요한가? | 조작 결과를 신뢰하기 어렵고 다음 학습 행동을 결정하기 힘들다. |
| Why 3 | 어떤 정보가 부족할 수 있는가? | 조작 직후 현재 상태와 변경 결과가 충분히 구별되지 않을 수 있다. |
| Why 4 | 상태가 구별되지 않으면 어떤 문제가 생기는가? | 완료·학습 중·미학습을 같은 행동이나 모호한 표시로 해석할 수 있다. |
| Why 5 | 설계에서 우선 해결할 근본 쟁점은 무엇인가? | 사용자의 조작과 화면의 상태 피드백 사이의 대응을 명확히 하는 것이다. |

**설계 결정:** B-5에서 완료·학습 중·미학습을 각각 표시하고, 완료 상태를 학습 중 또는 미학습으로 되돌리는 경로를 제공한다. 이는 Charverse의 표시·조작 설계이며, 리뷰에 등장한 원 앱의 상태 처리 문제를 직접 해결했다고 주장하지 않는다.

### 확장 검토 — 제품화 시 추가로 필요한 고려

| 항목 | 검토 내용 |
|---|---|
| 사용 기기 | 짧은 학습 세션은 휴대폰을 우선하고, 넓은 창에서는 목록과 보관함의 공간 활용을 확인한다. |
| AI 활용 기회 | 필기 입력의 획·방향 분석과 개인별 연습 피드백은 향후 제품화 시 검토할 수 있다. 현재 UI에는 사전 작성된 피드백 예시만 표시한다. |
| 상충 원칙 | 상세한 획 안내(P05·P06)는 오류 예방과 재인에 유리하지만, 정보량 증가는 간결성(P08)과 충돌할 수 있어 토글과 단계별 정보를 둔다. |
| 필요한 데이터 | 문자별 표준 글리프·획수·검증된 획순, 예문·발음, 사용자 동의 기반 필기 입력과 피드백 이력이 필요하다. |

## 1. 화면 목록과 흐름

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 글자 도감 및 학습 목록 (언어/즐겨찾기 허브 ↔ 글자 검색 리스트) | `lib/screens/a_list_screen.dart` | 첫 화면 | GET `/items` |
| B | 글자 학습 및 습관 분석 상세 (따라 쓰기 연습 & 획순 가이드) | `lib/screens/b_detail_screen.dart` | 쌓기(push) — A에서 글자 리스트 항목 누름 | GET `/notes?itemId=` (AI 필기 습관 피드백 탭) |
| C | AI 글쓰기 습관 정밀 진단서 | `lib/screens/c_result_sheet.dart` | 덮기(modal) — B의 "AI 진단서 보기" | 없음(미리 정한 결과) |
| D | 내 캐릭터 보관함 | `lib/screens/d_collection_screen.dart` | 쌓기(push) — A 우측 상단 캐릭터 아이콘 | 없음 |

```
A 첫 화면: 언어/즐겨찾기 5대 허브('ㄱㄴㄷ', 'あ', 'ア', '文', '⭐') ──(탭)──▶ A 글자 도감 리스트 (검색 + 태그/획수 필터 + 학습 상태)
       ▲                                                                                                  │
       └────────────────────────────────(언어 다시 선택 뒤로가기)─────────────────────────────────────────────┘
                                                                                                          │
                                                                                                쌓기(push)│
                                                                                                          ▼
B 상세 [옆으로(tab): 따라 쓰기·학습 상태 | AI 필기 피드백] ──덮기(modal)──▶ C AI 습관 진단서
│
└── A 우측 상단 캐릭터 아이콘 ──쌓기(push)──▶ D 내 캐릭터 보관함 (미확인 점 · 테마 선택)
```

- 전환 3방식: **쌓기**(push/pop) · **옆으로**(tab) · **덮기**(modal) — 흐름도의 화살표마다 하나를 적는다.
- 화면 A 안 표시 변화: 허브/목록 전환, 검색·태그·획수 필터, 즐겨찾기, 허브 항목 순서(우측 `=` 핸들 드래그), 글자별 학습 상태가 표시된다. 완료 글자는 캐릭터 배정 여부와 관계없이 목록 아래에 놓인다.
- 학습 진척도: 각 문자 영역에는 `학습 중 + 학습 완료 글자 수 / 전체 글자 수`를 표시한다. 즐겨찾기 영역은 진척도 대신 `n개 단어`를 표시한다. 학습 상태는 앱 실행 중 메모리에서 관리한다.
- 화면 B 안 표시 변화: 획순 가이드 ON/OFF, 캔버스 드로잉, 학습 완료↔학습 중 전환, 미학습으로 되돌리기를 표시한다.
- 화면 D 안 표시 변화: 캐릭터 선택, 미확인 캐릭터 읽음 처리, 테마 선택/해제는 메모리 안 상태로 표시한다. 테마 및 읽음 여부는 영구 저장하지 않는다.
- 적응형: 화면 A는 세로 목록을 사용한다. 화면 D는 `LayoutBuilder`에서 창 너비를 기준으로 열 수를 2~5열로 조정하고 타일 높이를 제한한다.

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### 문자 영역 허브 (A-7)
- **목적**: 학습할 문자 영역을 먼저 선택하게 해 162개 글자를 영역 단위로 탐색하도록 한다.
- **내용**: 한글·히라가나·가타카나·한자·즐겨찾기를 카드로 표시한다. 각 카드는 영역명과 학습 설명, 진행 수치를 보여 주고, 본문 탭은 목록으로 이동한다. 우측 `=` 핸들은 카드 순서를 조정한다.
- **의도**: 영역 진입과 재배열을 별도 조작으로 구분해 잘못된 화면 이동을 줄이고, 반복 사용하는 영역을 빠르게 찾게 한다(P02, P03, P07).

### 검색 및 태그 필터 (A-9)와 글자 목록 및 학습 상태 (A-2)
- **목적**: 글자 수가 많은 목록에서 필요한 글자를 찾고 현재 학습 상태를 바로 확인하게 한다.
- **내용**: 위에서부터 검색창, 일반 태그 칩, 획수 드롭다운, 결과 수, 글자 목록 순서로 배치한다. 태그 행이 창 너비를 넘으면 스크롤바를 두지 않고 마우스·터치 드래그로 좌우 이동한다. 글자 목록은 글리프·글자명·분류 태그·학습 상태를 한 행에 표시하고, 완료 글자는 목록 하단에 정렬한다. 즐겨찾기 별표는 행의 우측에 둔다.
- **의도**: 검색과 필터로 탐색 범위를 좁히고, 완료·미완료를 색상만이 아니라 텍스트로 구분해 현재 상태를 알아보게 한다(P01, P05, P06, P07, P08).

### 따라 쓰기 연습 캔버스 및 획순 가이드 토글 (B-3, B-8)
- **목적**: 학습자가 글자 실루엣과 획 번호·방향을 함께 보고 직접 쓰며 형태를 익히도록 돕는다.
- **내용**: 
  - 캔버스에는 모눈 기준선, 회색 글자 실루엣, 번호·방향 뱃지, 사용자가 그린 획을 겹쳐 표시한다(`B-3`).
  - `획순 가이드 ON/OFF` 칩(`B-8`)의 현재 상태에 따라 캔버스 안내를 전환한다.
  - 캔버스 아래 `획순·곡선 형태 안내판`(`B-9`)에는 번호·방향 기호·설명을 순서대로 배치한다.
- **의도**: 시각적 기준과 순서 정보를 동시에 제공하고, 익숙해진 사용자는 가이드를 끄고 직접 연습할 수 있게 한다(P01, P05, P06, P07).

### AI 필기 습관 피드백 목록 (B-7)과 진단서 모달 (C-1~C-4)
- **목적**: 목업 피드백 목록과 진단서 예시를 통해 학습 후 정보를 살펴보는 흐름을 구성한다.
- **내용**: B-7은 선택한 글자의 `/notes?itemId=` 결과를 로딩·오류·빈 상태와 함께 표시한다. C-1은 모달로 열고, C-2에서 대상 글자를 표시하며, C-3에서 획 방향성·획순 준수율·글자 균형도 예시를 보여 준다. C-4는 사전 작성된 진단 예시임을 안내한다.
- **의도**: 정보 조회 흐름을 연습 화면과 분리하고, 사용자에게 화면 데이터의 성격을 명확히 알려 준다(P01, P02, P09, P10).

### 캐릭터 보관함 및 미확인 캐릭터 (D-1~D-4)
- **목적**: 학습 완료로 획득한 캐릭터와 대응 글자를 모아 보고, 새로 획득한 캐릭터를 놓치지 않게 한다.
- **내용**: D-2 카드에는 캐릭터 이미지와 실제 글자명(ㅅ·い·キ·火)을 표시한다. 아직 조회하지 않은 캐릭터는 카드 우측 상단에 빨간 점을 표시하고, 해당 카드를 누르면 그 캐릭터만 조회 처리한다. A의 캐릭터 아이콘 배지는 보유 수가 아니라 미조회 캐릭터 수를 표시한다. D-3에서 선택한 캐릭터 테마는 선택 해제 시 기본 테마로 돌아간다.
- **의도**: 새 획득 상태를 눈에 띄게 전달(P01)하면서 읽음 상태를 사용자가 직접 해제(P03)하고, 전체 보유 목록을 효율적으로 관리(P07)한다.
- **범위**: 미확인 상태·학습 상태·테마 선택은 메모리에서만 유지하며 영구 저장하지 않는다.
